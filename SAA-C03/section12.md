## 1. S3 개요

**Amazon S3 (Simple Storage Service)** 는 AWS의 핵심 스토리지 서비스로, 무한 확장이 가능한 **객체 스토리지**다.

### 주요 사용 사례

| 카테고리 | 설명 |
|---|---|
| **Backup & Storage** | 파일 백업 및 스토리지 |
| **Disaster Recovery** | 리전 간 데이터 복구 |
| **Archive** | 장기 보관 아카이빙 |
| **Hybrid Cloud Storage** | 온프레미스 ↔ 클라우드 연결 |
| **Application Hosting** | 애플리케이션 배포 |
| **Media Hosting** | 비디오, 이미지 등 미디어 파일 |
| **Data Lakes & Big Data Analytics** | 대규모 데이터 분석 |
| **Software Delivery** | 소프트웨어 배포 패키지 |
| **Static Website** | 정적 웹사이트 호스팅 |

> 💡 **시험 포인트**:
> - S3는 **객체 스토리지**이며, 블록 스토리지(EBS)나 파일 스토리지(EFS)와 구분된다.
> - S3는 **리전 기반** 서비스지만 콘솔에서는 글로벌로 표시된다.

## 2. S3 버킷과 객체

### 버킷 (Bucket)

- **리전 수준(Region-level)**에서 생성되며, 이름은 **전 세계적으로 고유**해야 한다.
- 버킷 네이밍 규칙:
  - 대문자, 밑줄(`_`) 불가
  - 3~63자
  - IP 주소 형태 불가
  - 소문자 또는 숫자로 시작
  - `xn--` 접두사 불가
  - `-s3alias` 접미사 불가

### 객체 (Object)

**키(Key)** = 전체 경로 = **접두사(prefix)** + **객체 이름(object name)**

```
s3://my-bucket/my_folder/another_folder/my_file.txt
               ↑─────────────────────── prefix ─────↑ ↑──── object name ────↑
```

| 속성 | 설명 |
|---|---|
| **최대 객체 크기** | 5TB |
| **단일 PUT 최대 크기** | 5GB |
| **멀티파트 업로드 필수** | >5GB (100MB 초과 시 권장) |
| **Metadata** | 키/값 쌍 (시스템 또는 사용자 정의) |
| **Tags** | 최대 10개, 보안/수명주기 관리에 유용 |
| **Version ID** | 버전 관리 활성화 시 부여 |

> 💡 **시험 포인트**:
> - **5TB**는 최대 객체 크기, **5GB**는 단일 PUT 업로드 한도다.
> - **5GB 초과** 업로드 시 반드시 **멀티파트 업로드(Multi-Part Upload)** 사용.
> - S3에는 실제 디렉터리 개념이 없고, **키(Key)** 에 `/`가 포함된 것처럼 보일 뿐이다.

## 3. S3 보안 기초

### 보안 모델

#### User-Based (사용자 기반)
- **IAM Policies**: 특정 IAM 사용자에게 허용되는 API 호출 정의

#### Resource-Based (리소스 기반)

| 유형 | 설명 |
|---|---|
| **Bucket Policies (JSON)** | 버킷 전체 규칙; **교차 계정(cross-account)** 접근 허용 가능 |
| **Object ACL** | 세분화된 객체 수준 제어 (비활성화 가능) |
| **Bucket ACL** | 덜 사용됨 (비활성화 가능) |

### 접근 허용 조건

```
IAM principal이 S3에 접근 가능한 경우:
  (IAM 정책에서 허용) OR (리소스 정책에서 허용)
  AND
  명시적 Deny 없음
```

### 암호화 (Encryption)

- **암호화 키**를 이용한 객체 암호화 지원

> 💡 **시험 포인트**:
> - 버킷 정책은 **교차 계정 접근**을 허용하는 주요 수단이다.
> - **명시적 Deny**는 항상 Allow를 덮어쓴다.
> - ACL은 현재 **비활성화 권장** (Bucket Ownership Enforced).

## 4. S3 버킷 정책

### JSON 기반 정책 구조

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Principal": "*",
      "Action": "s3:GetObject",
      "Resource": "arn:aws:s3:::my-bucket/*"
    }
  ]
}
```

| 요소 | 설명 |
|---|---|
| **Effect** | `Allow` / `Deny` |
| **Actions** | 허용/거부할 API 목록 (예: `s3:GetObject`) |
| **Principal** | 정책을 적용할 계정 또는 사용자 |
| **Resource** | 버킷 및 객체 ARN |

### 주요 사용 사례

- **퍼블릭 접근 허용** (정적 웹사이트용)
- **업로드 시 객체 암호화 강제**
- **교차 계정 접근 허용**

### 퍼블릭 접근 차단 설정 (Block Public Access)

4가지 설정 유형:
1. 새 ACL로 생성된 퍼블릭 접근 차단
2. 모든 ACL로 생성된 퍼블릭 접근 차단
3. 새 퍼블릭 버킷/액세스 포인트 정책 차단
4. 기존 퍼블릭 버킷/액세스 포인트 정책 차단

> 💡 **시험 포인트**:
> - **Block Public Access**는 **계정 수준**에서 설정 가능 (실수 방지용 안전장치).
> - 퍼블릭 웹사이트 호스팅 시 이 설정을 **비활성화**해야 한다.

## 5. 정적 웹사이트 호스팅

- S3로 인터넷에서 접근 가능한 **정적 웹사이트** 호스팅 가능
- URL 형식:

```
http://bucket-name.s3-website-aws-region.amazonaws.com
또는
http://bucket-name.s3-website.aws-region.amazonaws.com
```

### 403 Forbidden 오류 발생 시

- 버킷 정책에서 **퍼블릭 읽기(s3:GetObject)** 가 허용되어 있는지 확인

> 💡 **시험 포인트**:
> - 403 에러 → **버킷 정책 미설정** 또는 Block Public Access 활성화 상태.
> - 정적 웹사이트 호스팅은 **HTML, CSS, JS** 등 정적 파일만 지원 (서버 사이드 로직 불가).

## 6. S3 버전 관리

- **버킷 수준(Bucket Level)**에서 활성화
- 동일한 키로 업로드 시 **버전이 증가** (덮어쓰기 아님)

### 동작 방식

| 상황 | 결과 |
|---|---|
| 버전 관리 활성화 전 파일 | 버전 ID = **"null"** |
| 버전 관리 일시 중단(Suspend) | 이전 버전 **삭제되지 않음** |
| 파일 삭제 | **삭제 마커(Delete Marker)** 추가 |
| 삭제 복원 | 삭제 마커를 제거하면 복원 |

### 주요 이점

- 의도치 않은 삭제로부터 보호
- 이전 버전으로 롤백 가능

> 💡 **시험 포인트**:
> - 버전 관리 **일시 중단**은 기존 버전을 삭제하지 않는다.
> - 파일 삭제 시 실제 삭제가 아닌 **삭제 마커**가 추가된다.
> - 영구 삭제는 **특정 버전 ID를 지정**해서 삭제해야 한다.

## 7. S3 복제 (CRR & SRR)

### 복제 유형

| 유형 | 전체 이름 | 주요 용도 |
|---|---|---|
| **CRR** | Cross-Region Replication | 규정 준수, 지연 시간 감소, 계정 간 복제 |
| **SRR** | Same-Region Replication | 로그 집계, 운영/테스트 환경 간 실시간 복제 |

### 설정 요건

- 소스 및 대상 버킷 모두 **버전 관리 활성화** 필수
- S3에 적절한 **IAM 권한** 부여 필요
- 복제는 **비동기(Asynchronous)** 방식

### 복제 동작 규칙

- 활성화 이후 **새로 생성된 객체만** 복제됨
- 기존 객체 복제 → **S3 Batch Replication** 사용
- **삭제 마커** 복제는 선택 사항 (옵션으로 활성화)
- **영구 삭제(특정 버전 ID 삭제)** 는 복제되지 않음 (악의적 삭제 방지)
- **복제 체이닝 불가**: bucket1 → bucket2 → bucket3 설정 시, bucket1의 객체가 bucket2를 거쳐 bucket3으로 자동 복제되지 않음

> 💡 **시험 포인트**:
> - CRR/SRR 모두 **버전 관리 활성화**가 전제 조건이다.
> - **삭제 마커 복제**는 기본값이 아니며, 명시적으로 활성화해야 한다.
> - **영구 삭제(버전 ID 지정)**는 절대 복제되지 않는다.
> - 복제 활성화 이전 기존 객체는 **S3 Batch Replication**으로 별도 처리해야 한다.
